# CLAUDE.md — конституция проекта Course Dashboard

## Что это
Дашборд преподавателя курса «Управление агентной разработкой»: читает `.md`-артефакты из публичных репозиториев 25 студентов (GitLab/GitHub API), показывает матрицу «репозиторий × занятие» и подсвечивает **структурные разрывы связности** между артефактами. v1 — приватный однопользовательский инструмент (только преподаватель).
Это **демо-проект курса**: он же учебный пример, он же реальный инструмент. Разрабатывается агентно, live на занятиях.
**Стек:** Python 3.12+ · FastAPI · SQLAlchemy 2.x (Mapped) + Alembic · SQLite (WAL-mode) · Jinja2 + HTMX · bcrypt + sessions · LLM ядра: deepseek-v4-flash (ADR-004, эвал pending) → ADR-002 (уточнён ARCHITECTURE.md v3).

Операционализация — ADR-001 (LLM-агент по правилам). Правило исполнено, не отменено: смена рубрики/модели по-прежнему требует прогона golden set.
- **ВСЕГДА** прогонять golden set (`evals/golden-set.md`) при любой смене рубрики или модели ядра — расхождение с эталонным вердиктом = регрессия.
- **НИКОГДА** не добавлять студенческий или публичный интерфейс — BR-4: v1 teacher-only by design.
- **ВСЕГДА** spec-driven: сначала acceptance criteria конкретного FR/US, потом код.
- **ВСЕГДА** помечать выводы из синтетических интервью как гипотезы, не факты.
- Единственный канонический PRD — `product/prd.md`. Старые версии — только в `archive/`, их не править и не цитировать как актуальные.
- User stories канонически живут в `product/user-stories/` — PRD их не дублирует (защита от рассинхрона АП-14).
- **ВСЕГДА** именовать ветку и коммит с ID тикета: ветка `S5-auth`, коммит `S5: add login/logout with lockout`. Это трассирует код к задаче из трекера (`plans/plan.md` → GitHub Issues).
- **Агентные сессии работают только в собственных worktree** (`git worktree add ../cd-<ID> -b <ветка> main`); основное дерево `course-dashboard/` — территория CEO, его HEAD сессии не переключают. Merge в main и push — кнопка CEO. Основание: три инцидента параллельной работы 2026-07-30/31 (переключение чужого HEAD, потерянные файлы, merge не в ту ветку).
- **`.venv` — общий ресурс всех сессий, его НЕ создавать, НЕ пересоздавать и НЕ наполнять.** Нет интерпретатора или пакетов — остановись и доложи; зависимости ставит только CEO по `requirements.lock`. Основание: инцидент №4 параллельной работы 2026-08-14 — venv затёрт пустым во время трёх параллельных сессий, правило worktree общие ресурсы не покрывало (решение CEO 2026-08-14).

## Стандарт документации
1. **Код и документация — один MR.** Если изменение затрагивает то, о чём говорят `README.md`, `INDEX.md` или `ARCHITECTURE.md`, эти файлы обновляются в том же MR. `memory/MEMORY.md` вне стандарта — это рабочая память сессий, её ритм «каждая сессия», а не «каждый MR».
2. **Устаревшее заменяется, а не дополняется.** История изменений живёт в `CHANGELOG.md`; в основных файлах — только актуальное состояние.
3. **Один факт живёт в одном месте.** Остальные файлы ссылаются на канонический источник, а не дублируют его.
4. **Доки не затронуты — обоснование в MR.** Если изменение документацию не затрагивает, в описании MR пишется: «докам обновление не требуется, потому что …».
