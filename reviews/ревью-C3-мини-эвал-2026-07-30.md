## Что проверено и сошлось

- **Железное правило соблюдено.** Дифф не создаёт файлов в `app/` (нет `coherence_analyzer`/`llm_client`); `grep evals app/` пуст — приложение скрипт не импортирует. Зависимость односторонняя: `evals/` → `app/` (переиспользует `GitClient` и `settings`), это допустимо. Скрипт — механизм снятия гейта, о чём прямо сказано в шапке файла.
- **Контракт §5.2 ARCHITECTURE воспроизведён точно** (`validate_response`, `evals/mini_eval.py:199-236`): обязательные поля, домены `verdict ∈ {ok, break}` / `confidence ∈ {high, medium, low}`, целостность `checked == found + excluded + lost`, `points` — список ≤5, JSON в fence-блоке извлекается. Ретрай ровно один, затем `deferred(parse_error)` (`run_pair`) — буква §5.2 («не 3 ретрая с усиленным промптом»).
- **Краевые случаи по линзам:** fence-блок — принимается (есть тест); отрицательные счётчики — отклоняются (`isinstance(int) and c >= 0`); `points` не список — отклоняется; всё это → ретрай → deferred, мусор в отчёт не попадает. Поведение при верхнем регистре вердикта — см. находку 4.
- **Рубрики не дублируются.** Тексты рёбер `prd→data_model` и `data_model→architecture` читаются из `app/config.yaml` (`config_rubric`), не копируются. `GENERIC_RULE` применяется только к рёбрам, которых в config.yaml нет (в нём ровно 2 ребра — проверено), — это не дубль, а каркас v1 из `evals/golden-set.md`. Промпт (`PROMPT_TEMPLATE`) соответствует каркасу v1: роль, правило ребра, вердикт/уверенность/счётчики/точки ≤5 (сущность | цитата A ≤15 слов | что искал в B) / заметки ≤3 строк — плюс требование строгого JSON.
- **Детерминизм:** `temperature: 0.0` и `response_format: {"type": "json_object"}` в вызове API. `llm_model` в отчёте берётся из той же `settings.deepseek_model`, что ушла в запрос, — модель в отчёте не может разойтись с фактически использованной (канон Б1 соблюдён конструктивно).
- **Честность отчёта:** эталоны заданы только у GS-1/GS-2 (`etalon="ok"|"break"`, совпадает с golden-set.md вплоть до эталонных точек — «дрейф слепой зоны» как ложная сработка, «Оксана потеряна молча»); у реальных пар `etalon=None`, колонка «Совпал» — «—», и отчёт прямо пишет: «Эталоны есть только у GS-пар; вердикты реальных пар выносит на сверку CEO». Итог считает совпадения только по GS; deferred у GS-пары честно не засчитывается как совпадение.
- **Приватность — кеш:** `evals/pairs/` добавлен в `.gitignore` и не отслеживается (`git ls-files evals/` — только golden-set.md и mini_eval.py); имена файлов кеша строятся из кодов (`С-01--REQUIREMENTS.md.txt`), не из ФИО. Про сам `REPOS` — находка 1.
- **Tests first реален:** коммит `2c2ba91` — только тесты (красные: модуля нет), реализация — следующим коммитом. 15 тестов проверяют поведение через инъекцию `call` (состав пар, промпт, schema-check, ретрай→deferred, mismatch эталона, llm_model в отчёте), к внутренностям реализации не привязаны, сеть не трогают.
- **Прогоны:** `pytest tests/test_mini_eval.py -q` — **15 passed**; `ruff check evals/ tests/test_mini_eval.py` — чисто. Заявление CHANGELOG «178 → 193» подтверждено: `--collect-only` собирает ровно 193.
- **Соответствие plan.md §4 волна 1:** «GS-1/GS-2 + 4–6 пар из реальных репо» — 4 пары, в диапазоне; предусловие P2 (`CD_DEEPSEEK_API_KEY`) проверяется с внятной ошибкой.
- **Диагноз бага клиента (коммит 3) подтверждён:** `app/clients/git_client.py:106` — GitLab `commits/{ref}` кодирует ref через `quote(ref)` (по умолчанию `safe='/'`), слэш в `feat/agentic-engineering-setup` не экранируется → 404. Обход через `branches/{quote(ref, safe='')}` корректен.
- **Стандарт документации:** golden-set.md получил инструкцию прогона, CHANGELOG и .gitignore — в том же наборе коммитов. README/INDEX описывают `evals/` обобщённо и не соврали; см. находку 7.
