## Что проверено и сошлось

- **Репро-тест действительно ловит баг.** `tests/test_repro_404_mtb_knowledge_hub.py` прогнан на клоне репозитория с кодом `14e68fd~1` (только тест из фикса поверх) — падает с `repo_unavailable` по mtb-knowledge-hub; на текущем main — зелёный. Красный→зелёный переход реален, тест не «зелёный от рождения».
- **Код соответствует ADR-006:** новый метод `GitClient.fetch_default_branch` (`app/clients/git_client.py:111-124`), детект при импорте (`app/services/csv_importer.py:54-60`), сверка всех активных репо перед обходом (`app/services/sync_orchestrator.py:446-456`) — все три механизма из ADR на месте, деградация при недоступности API — как описано.
- **Заявление ADR «тесты 120 → 121» подтверждено:** на `14e68fd` собирается ровно 121 тест.
- **Краевые случаи с корректной деградацией:** приватный репозиторий без доступа (GitHub маскирует под 404) → `GitRepoUnavailableError` глотается, остаётся `main`, дальше честный исход `repo_unavailable`; протухший токен → `auth_failed` не теряется (пре-цикл глотает, основной цикл выставляет исход); rate-limit → `skipped_rate_limit` сохраняется. Ветка, отличная и от `main`, и от `master`, обрабатывается (детект берёт фактическое имя из API, не перебирает кандидатов). Смена default-ветки ПОСЛЕ импорта чинится сама на следующем обходе — сверка идёт каждый обход по всем репо.
- **Идемпотентность сверки:** запись только при фактическом изменении (`if actual != repo.default_branch`), повторные обходы — no-op; append-only журналы не затронуты.
- `ruff check .` — чистый; `pytest` — 177/178 зелёных (единственное падение не связано с ADR-006 — см. находку 9).
- Правки чужих тестов (`test_csv_import.py`, `test_reconcile.py`, `test_sync_orchestrator.py`) — только дополнение фейков новым методом контракта, требования тестов не ослаблены.
