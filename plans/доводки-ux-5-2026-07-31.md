## C5 — Принудительный пересчёт вердиктов на русский · P0

**Трассировка:** решение CEO №2; C4/#64 (русский выход); железное правило golden set.
**AC:** версии всех рубрик рёбер в `config.yaml` подняты (+0.1, текст без изменений — пересчёт четвёрок, не смена правил); после reload-config у пар нет валидных вердиктов на новые четвёрки → следующий обход пересчитывает всё русским промптом; старые вердикты остаются в журнале (append-only). Гейт: перепрогон golden set (запись в golden-set.md).
**Негативные:** обход без ключа LLM — пары честно «проверяется», ничего не потеряно.

## D23 — Дубль artifact_def: guard + чистка · P0

**Трассировка:** решение CEO №1; verified-находка фокус-групп (prd/`product/prd.md` ×2, занятие 5).
**AC:** реконсиляция (`config_manager.reconcile`) идемпотентно удаляет дубли artifact_def по ключу (занятие, роль, паттерн) — остаётся старейший, снапшоты дубля удаляются (мусор бага, решение CEO; в сводке реконсиляции — счётчик `deduped`); повторный прогон — 0 изменений. Чистка боевой БД = штатный `POST /admin/reload-config` после deploy (ручной SQL не нужен), бэкап перед deploy обязателен (README).
**Негативные:** дублей нет — reconcile ничего не трогает; дубль с разными паттернами — не дубль.

## D24 — Хронология защиты: «перемещён» + MR-события · P0

**Трассировка:** решение CEO №5 (P0); находки «флаппинг» и «MR-даты не в ленте» (группа защиты — критично).
**AC:** (1) пара «исчез»+«появился» одной роли в одном обходе схлопывается в событие «перемещён: старый → новый путь» (одна строка); (2) в ленту хронологии добавлены MR-события по датам хостинга: «MR !N (ветка) — merged ДД.ММ» из наблюдений последнего обхода (независимые даты против «я сдавал раньше»); MR без даты хостинга — не рисуется в ленте (остаётся в свёрнутой таблице).
**Негативные:** «исчез» без «появился» (реальное удаление) — остаётся «исчез»; репо без MR — лента без MR-событий.

## D36 — Дело защиты: шапка-резюме + «мимо ревью» + «погашенных: 0» + прямой вход · P0

**Трассировка:** решения CEO №3, №4, №5; FR-13/US-C2.
**AC:** (1) шапка-резюме: «сдано X/M · разрывов: N · MR: K, из них мимо ревью: J · работа с ДД.ММ по ДД.ММ» (границы — по MR-датам хостинга, при их отсутствии — по датам коммитов/наблюдений); (2) секция погашенных показывается всегда — при нуле строка «погашенных разрывов: 0» (tests-change: негативный AC D19 «секция не рисуется» отменён решением CEO №3); (3) `GET /defense` — нейтральный список студентов (только имя репо + ссылка на дело, БЕЗ статусов и счётчиков — на проекторе нет чужих результатов), ссылка на него из матрицы.
**Негативные:** нет MR и нет снапшотов — резюме с прочерками, не падение; список /defense при пустом реестре — «реестр пуст».
