## C4 — Русский выход ядра · P0

**Трассировка:** FR-5 (структурированный выход — «заметки преподавателю»), BR-2 (выход читает человек), железное правило golden set (смена промпта = обязательный перепрогон).
**Проблема (все три группы):** notes и why в вердиктах приходят на английском («No corresponding test file in B…») — недоверие («сырой вывод нейронки»), непоказуемо на защите.

**Критерии приёмки:**
- Промпт `llm_client` явно требует: все свободнотекстовые поля выхода (`notes`, `why` в точках) — на русском языке; названия сущностей и цитаты остаются на языке документа студента (цитата — дословная, её не переводим).
- Валидатор выхода не меняется (язык не валидируем машинно — это инструкция промпта, не схема).
- **Гейт:** перепрогон golden set после смены промпта — вердикты GS-1/GS-2 совпадают с эталонами; прогон зафиксирован в `evals/golden-set.md` с датой и моделью.
- Существующие вердикты в БД не трогаем (журнал append-only); новые пары и пересчёт изменённых четвёрок придут по-русски. Старые англоязычные — уйдут естественным пересчётом при изменении документов; для защиты 20.08 при необходимости CEO дёргает пересчёт руками (снятие override/смена рубрики — вне скоупа C4).

**Негативные сценарии:** LLM вернула английский вопреки инструкции — вердикт валиден (схема не нарушена), деградация приемлема; тест промпта — контрактный (инструкция присутствует в собранном промпте).
**Документы:** golden-set.md (запись прогона), CHANGELOG; PRD не меняется (язык — качество реализации FR-5, не новое требование).

## D19 — Дело защиты v2 · P0

**Трассировка:** FR-13/US-C2 (уже в PRD v2.7), FR-9 (доказательная цепочка), находки группы «защита» (хронология не доказывает).

**Состав и критерии приёмки:**
1. **Шапка:** «Защита: <короткое имя репо>» + полный URL мелко (не простыня); дата открытия режима.
2. **Вердикт по-русски крупно:** notes — основной текст карточки разрыва (стиль: крупнее метаданных); файловая детализация точек — по раскрытию (`<details>`), не стеной.
3. **Хронология доказательная:**
   - Дано: снапшоты с `source_commit_sha`. Тогда таблица схлопнута до **переходов состояний** (появился / статус изменился / исчез) — не более одной строки на переход роли; полный лог — по раскрытию.
   - Даты дедлайнов: строки-вехи «занятие N — <дата>» (из `lesson.date`) вставлены в хронологию — видно «тесты появились через 4 дня после занятия 11».
   - **Дата коммита:** в снапшот добавляется `source_commit_date` (миграция + сбор в обходе из Git API; для старых снапшотов — NULL, показываем дату наблюдения с пометкой «зафиксировано обходом»). Негативный сценарий: API не отдал дату — NULL, не падение.
   - Время — без микросекунд, формат ДД.ММ ЧЧ:ММ.
4. **Возвращены свёрнутыми:** MR-история (номер, ветка, состояние, дата merge — независимые даты против «я сдавал раньше») и погашенные разрывы («разрыв X→Y снят преподавателем ДД.ММ» — история решений легитимизирует оценку; без цитат и кнопок).
5. Кнопок FR-10 по-прежнему нет; данных группы по-прежнему нет (регресс-тесты D18 — контракт).

**Негативные сценарии:** репо без MR-наблюдений — секция не рисуется; ни одного погашенного — секция не рисуется; все снапшоты одного коммита — хронология честно показывает один хеш (не выдумывать различий).
**Документы:** data-model.md (`source_commit_date` §1.9), ARCHITECTURE §5 (шаг обхода), CHANGELOG; PRD не меняется — детализация FR-13.

## D20 — Сводная колонка строки + две сортировки · P1

**Трассировка:** J1/J3, цель §4 «≤5 минут»; находка «сортировка врёт» + «разрывы за скроллом» + «розовая стена».
**Критерии приёмки:**
- Слева, рядом с именем репо (в закреплённой зоне): сводка строки «⚠ N» (уникальные разрывы, как D15) и «X/M» (сдано ролей из ожидаемых; found+partial считаются сданными с точностью до BR-3 — partial и есть «сдано криво», в счётчик X входит; шильдик «мимо ревью: K» при K>0 — сигнал процесса с матрицы занятий).
- Две сортировки в шапке: «по разрывам» (текущая D15) и «по отставанию» (по возрастанию X/M); подпись «сначала проблемные» уходит.
- Колонка «Разрывы» справа удаляется (сводка переехала влево — один факт в одном месте).
**Негативные сценарии:** пустая строка (0/M, 0 разрывов) — сортировка «по отставанию» ставит её первой; обе сортировки стабильны к порядку реестра.
**Документы:** CHANGELOG; тесты D15 на счётчик и стабильность — контракт, переносятся на новую колонку с пометкой tests-change (перемещение представления, требование не менялось — счётчик и стабильность те же).

## D21 — Честная ячейка и видимое курирование · P1

**Трассировка:** FR-4/FR-5 (итог ячейки), FR-10 (кнопка есть, но её не находят — находка группы A).
**Критерии приёмки:**
- Ячейка «есть» с активным разрывом: словесный итог «сдано, но разрыв» вместо «есть» (снимает конфликт «зелёное + бордовое»).
- Чип разрыва обрезается до 2 строк с многоточием (CSS line-clamp), полный текст — в модалке; название сущности не сокращается до бессмыслицы (первые ~80 символов).
- Кнопка «ложный разрыв» в модалке — видимая кнопка-действие в блоке разрыва (не текстовая строка в подвале карточки ребра), с подписью «отметка обратима».
**Документы:** CHANGELOG; докам PRD обновление не требуется — представление.

## D22 — Полировка · P2

**Трассировка:** доверие/полировка (группа B: «4/10 отполированность»), мелочи всех групп.
**Состав (каждый пункт — самостоятельный AC):** легенда без жаргона («не наблюдался» → «нет данных», «сдача через MR» → «сдача через merge request (запрос на слияние)»); переносы в колонке репо (word-break без разрыва в случайном месте); URL в шапках модалки и карточки → ссылка «открыть репозиторий»; «защита» → «защита проекта»; кнопка «обновить сейчас» на стикере актуальности (POST /sync с подтверждением); пустые MR-колонки матрицы занятий схлопываются в одну «занятия 11–13: сдача через MR»; таймстемпы интерфейса без микросекунд везде.
**Документы:** CHANGELOG.
