# Протокол совещания: приоритизация проверки заданий курса (по гэп-анализу 2026-07-28)

**Дата:** 2026-07-28 (поздний вечер, после эфира занятия 13)
**Вопрос:** что из предложений гэп-анализа «задания курса ↔ возможности дашборда» берём в скоуп до защиты (20.08; дедлайн прототипа 6.08), в каком порядке, что вычёркиваем.
**Повестка:** `../../digital-twin/staging/гэп-анализ-задания-vs-дашборд-2026-07-28.md` (T1/T2/T3/T5, рёбра 2→8, FR-11, канонизация путей).
**Состав:** все шесть ролей (повестка пересекается со speaks_on каждой). Фасилитатор — ИИ, без голоса.
**Решения:** CEO (Виталий Генаров), шесть развилок, 2026-07-28.

## Позиции (уверенность до → после спора)

- **Продакт (8→8; 6 по «FR-12 в PRD до тикета»):** в код — только трассируемое к утверждённым FR; порядок сдачи занятия 11 сделал FR-4 фактически ложным — закрытие обязано войти в скоуп; FR-11 и T5 — вне состава v1. Снял максимализм: US для FR-12 — 20 строк в той же сессии.
- **Архитектор (8→9 по минимальной форме):** T2/T3 — носитель есть; полный T1 — второй домен наблюдения (новая сущность, драйвер, ADR); минимальная форма — снапшоты с головы открытого MR без новой сущности; T5 — чужой домен без драйвера.
- **Тестировщик (9→9):** T1 без критериев приёмки и негативных сценариев MR-домена (squash/rebase/amend/force-push, отрицание в тексте вердикта) не берётся; рёбра — только с парами golden set и зафиксированной моделью; T2 — самый тестируемый пункт.
- **Девопс (8→7):** главный операционный риск — продукт на ноутбуке (cron/VPS); MR API требует scope `read_api` (проверить до тикета); миграции — только с работающим downgrade; ключи — env/chmod 600.
- **Финдир (7→8 по T5/FR-11; 6 по «T1 дорог»):** T5 — вычеркнуть (девять URL глазами); FR-11 не активировать; T1 — узкая сегодняшняя база (MR у 1 из 9), но скорость агентов снижает оценку стоимости.
- **Предметный эксперт (9→9):** ложное «нет» сдавшим через MR — вердикт, который студент справедливо оспорит (цена ошибки на защите, PRD §11); маркеры объявлены студентам как машинный контроль — курс сам нарушает своё правило «политика в тексте ≠ машинный гейт»; пробы — только к объявленным требованиям; рёбра без материала дадут пустоту.

## Карта конфликтов

- **К1** — глубина закрытия MR-канала: полный FR-12 vs обход головы MR vs пометка (ценность объявленного контроля против стоимости и хрупкости машинной проверки).
- **К2** — рёбра: веха плана «8» против отсутствия материала (код/тесты у 1 из 9) и регрессионного гейта.
- **К3** — пробы: дешёвое довыполнение FR-4 vs скрытое изменение BR-3.
- **К4** — FR-11: объявленные требования к качеству против решения CEO держать его в v2.

## Развилки и РЕШЕНИЯ CEO

1. **Мини-эвал DeepSeek** → **ключ до занятия 14** (за — все роли). CEO кладёт `CD_DEEPSEEK_API_KEY` в .env; прогон GS-1/GS-2 + пары С-01/С-02; сходимость → ADR-004 Accepted, гейт Фазы 0 снят, ядро (эпик #17) в разработку.
2. **MR-канал** → **полный FR-12 сейчас** (позиция эксперта и продакта). Вето остаются порядком работ: (а) FR-12 с US и критериями в PRD §5; (б) список негативных сценариев MR-домена; (в) драйвер D40 + ADR «почему строим вторую сущность»; (г) миграция MrObservation с работающим downgrade; (д) до постановки — проверить scope glab-токена (`read_api`). До готовности FR-12 в матрице — честная пометка занятий 11+ вместо «нет».
3. **Рёбра** → **8 по плану** (позиция продакта; веха pre-defense целиком). Условие тестировщика в силе: каждая новая рубрика — с парой в golden set, `llm_model` зафиксирована. Осознанная цена: plan→code и code→tests сегодня пусты у 8 из 9.
4. **Пробы содержимого (T2)** → **узкая редакция** (позиция продакта): пробы выполняются и показываются отдельным признаком карточки («раздел X не найден»), статус ячейки не меняют — BR-3 не тронут. Ограничение эксперта: только объявленные требования; field_journal/test_map — после канонизации путей на занятии 14.
5. **T5 (URL прототипов)** → **вычеркнут**. Уточнение CEO: URL появятся только после разворачивания (занятие 15 / 6.08) — проверять пока нечего. Запись «почему не строим»: девять URL проверяются глазами; контроль недели 8 закрывает человек.
6. **FR-11** → **пилот вне продукта** (позиция эксперта): одна рубрика шага (README, к занятию 15) прогоняется скриптом вручную, результат — материал занятия и первые данные пилота точности v2; в код и БД v1 не попадает; модель прогона фиксируется. Решение 09.07 (FR-11 = v2) не отменяется.

**Согласовано без развилок:** merge стека первой итерации — предусловие; T3 (роли артефактов) — enum + config.yaml; канонизация путей полевого журнала и карты тестов — строкой на занятии 14; статус «нет» для занятий 11+ недопустим ни в одном сценарии; BR-2 (никаких оценок) не нарушается ничем из принятого.

## Несогласные голоса (не удалять)

- **Финдир:** полный FR-12 — самая дорогая работа списка при базе «MR у одного репозитория из девяти»; остался при мнении, что достаточно обхода головы MR.
- **Архитектор:** предпочёл бы минимальную форму без второго домена; принял решение при условии драйвера и ADR.
- **Тестировщик:** проверки порядка коммитов считает хрупкими по природе (squash/rebase); зафиксировано как требование к негативным сценариям FR-12, скепсис сохраняется.
- **Предметный эксперт:** пилот FR-11 вне продукта считает полумерой — объявленные требования к качеству остаются без машинной проверки до v2.
